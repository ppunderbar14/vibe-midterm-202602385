## 앱 소개

고객이 음료와 옵션을 골라 주문하고 관리자가 주문 내역·제조 상태·재고를 확인하는 단일 페이지 웹앱이다. HTML/CSS/바닐라 JavaScript만 사용하며 빌드, 외부 API, 유료 서비스 없이 GitHub Pages에서 동작하도록 구현할 예정이다.

| 메뉴 | 가격 | 초기 재고 |
| --- | ---: | ---: |
| 아메리카노 | 3,000원 | 20잔 |
| 카페라떼 | 3,500원 | 15잔 |
| 바닐라라떼 | 4,000원 | 15잔 |
| 카페모카 | 4,500원 | 10잔 |
| 초코라떼 | 4,000원 | 10잔 |

모든 메뉴에 샷 추가(+500원), 시럽 추가(+0원)를 각각 선택할 수 있다. 같은 메뉴라도 옵션이 다르면 별도 장바구니 항목으로 처리한다.

## 현재 사용법

### 고객

1. 고객 화면에서 메뉴와 남은 재고를 확인한다.
2. 샷·시럽 옵션을 선택하고 장바구니에 담는다.
3. 수량을 수정하거나 항목을 삭제하고 총액을 확인한다.
4. 같은 메뉴라도 옵션이 다르면 별도 항목이다. 같은 옵션을 다시 담으면 수량이 합쳐진다.
5. 수량은 1 이상의 안전한 정수만 허용한다. 입력 후 Enter 또는 다른 곳으로 포커스를 옮기면 반영된다. 잘못된 입력은 기존 값으로 돌아간다.
6. 모든 옵션의 합계가 해당 메뉴 재고를 넘으면 담기·수량 증가를 차단한다. 장바구니 조작으로 재고는 줄어들지 않는다.

주문 버튼은 **“주문 기능 준비 중”**으로 비활성화되어 있다. 현재는 주문을 접수하지 않는다.

### 관리자

같은 페이지의 관리자 화면 버튼을 누르면 주문 기능 준비 안내와 메뉴별 초기 재고가 표시된다. 실제 주문 현황과 제조 완료 처리는 다음 단계다. 이 화면은 시험용이며 로그인·인증 기능은 없다.

### 저장과 복원

현재 localStorage를 읽거나 쓰지 않는다. 장바구니는 화면 전환 동안 유지되지만 새로고침하면 비워진다. 기존 브라우저 저장 데이터도 건드리지 않는다.

다음 단계에서 주문·재고·장바구니를 단일 JSON으로 저장하고 복원할 예정이다. 저장 성공 후 상태 반영, 주문 전체 재고 검사, 제조 완료 시 재차감 금지 등의 최종 규칙은 PRD를 따른다.

## 실행과 검증

`index.html`을 브라우저에서 열면 실행된다. 검증할 때는 프로젝트 폴더에서 `python3 -m http.server 8765 --bind 127.0.0.1`로 정적 서버를 띄우고 `http://127.0.0.1:8765`에 접속했다. Python은 로컬 검증용일 뿐 앱 실행/배포 의존성이 아니다.

실제 Chrome에서 다음을 확인했다.

- 샷 아메리카노 2잔 7,000원, 기본 카페라떼 1잔 추가 후 10,500원.
- 옵션별 분리·동일 옵션 병합, 수량 변경·삭제 후 금액 갱신.
- 옵션 합산 아메리카노 20잔에서 추가 담기·수량 증가 차단, 표시 재고 20잔 유지.
- 빈 값·0·음수·소수·비숫자·안전 정수 범위 초과 거부와 이전 값 복원.
- 마지막 항목 삭제 후 0잔/0원·빈 안내, 삭제 후 포커스 복원, 새로고침 시 초기화.
- 키보드 Space/Enter 옵션·담기·수량·삭제·화면 전환, 두 화면의 360/390/768/1280px 가로 넘침 없음.
- CSS·JS 로드 및 관찰된 콘솔 오류/경고 없음. 자세한 실제 결과는 PROMPTS의 002에 기록했다.

실물 모바일 기기, 다른 브라우저, 스크린리더 음성 출력, 실제 Pages URL은 미검증이다. 주문·저장 등 다음 단계 기능은 테스트하지 않았다.

## 앱 소개

고객이 음료와 옵션을 골라 주문하고 관리자가 주문 내역·제조 상태·재고를 확인하는 단일 페이지 웹앱이다. HTML/CSS/바닐라 JavaScript만 사용한다. 빌드, 외부 API, 유료 서비스가 없으며 GitHub Pages용 정적 파일로 구성했다. 실제 배포는 아직 진행하지 않았다.

| 아메리카노 | 3,000원 | 20잔 |

모든 메뉴에 샷 추가(+500원), 시럽 추가(+0원)를 각각 선택할 수 있다. 같은 메뉴라도 옵션이 다르면 별도 장바구니 항목으로 처리한다.

## 현재 사용법

### 고객

1. 고객 화면에서 메뉴와 남은 재고를 확인한다.
2. 샷·시럽 옵션을 선택하고 장바구니에 담는다.
3. 수량을 수정하거나 항목을 삭제하고 총액을 확인한다.
4. 같은 메뉴라도 옵션이 다르면 별도 항목이다. 같은 옵션을 다시 담으면 수량이 합쳐진다.
5. 수량은 1 이상의 안전한 정수만 허용한다. 입력 후 Enter 또는 다른 곳으로 포커스를 옮기면 반영된다. 잘못된 입력은 기존 값으로 돌아간다.
6. 모든 옵션의 합계가 해당 메뉴 재고를 넘으면 담기·수량 증가를 차단한다. 장바구니 조작으로 재고는 줄어들지 않는다.

7. **주문 확정**을 누른다. 입력 중인 수량을 검사하고 모든 메뉴의 합산 재고가 충분한 경우에만 주문과 재고를 함께 저장한다. 빈 장바구니와 처리 중에는 버튼이 비활성화된다.
8. 성공하면 장바구니가 비워지고 주문 확인에 주문번호·시각·확정 항목·총액·접수 상태가 표시된다. 새로고침 후에도 기록이 유지된다.

수량 입력이 잘못되었다면 기존 값으로 되돌리고 그 주문 시도를 중지한다. 수량을 확인하고 다시 주문할 수 있다. 재고 부족 시 부족 메뉴와 가용 수량을 표시하며 주문 전체를 차단한다. 품절 메뉴는 담을 수 없다.

### 관리자

같은 페이지의 관리자 화면 버튼을 누르면 관리자 주문 기능 준비 안내와 메뉴별 실제 남은 재고·품절 상태가 표시된다. 실제 주문 현황과 제조 완료 처리는 다음 단계다. 이 화면은 시험용이며 로그인·인증 기능은 없다.

### 저장과 복원

- 단일 키 `cafe-order-app`의 `schemaVersion: 1` JSON에 재고·장바구니·주문·다음 번호를 저장한다. 키가 없을 때만 초기 상태를 생성한다.
- 담기·수량 변경·삭제와 주문은 복사본 검증 후 저장하며, 저장 성공 후에만 메모리와 화면을 갱신한다. 장바구니 조작은 재고를 차감하지 않는다.
- 주문은 `ORD-0001`부터 증가하고 새로고침 후에도 다음 번호를 유지한다. 주문 당시 이름·가격·옵션·수량·금액을 보존한다.
- 손상 JSON·알 수 없는 버전·잘못된 저장값은 덮어쓰지 않는다. 저장소 읽기·쓰기 오류도 성공으로 처리하지 않으며 변경을 막고 오류를 알린다. 저장소 설정·용량 문제를 해결한 뒤 새로고침해 확인한다. 자동 초기화나 데이터 삭제 버튼은 없다.
- 복원 장바구니가 재고를 넘으면 부족 안내가 나온다. 수량을 줄이거나 삭제할 수 있으며 충분해질 때까지 주문은 차단된다.
- 데이터는 같은 브라우저·같은 사이트 주소에 저장된다. 주소가 다른 로컬 실행과 Pages, 다른 기기는 데이터를 공유하지 않는다. 브라우저 데이터를 삭제하면 기록이 사라질 수 있다.
- 기본 사용 범위는 단일 탭이다. 여러 탭의 완전한 동시성은 보장하지 않는다.

## 실행과 검증

프로젝트 폴더에서 `python3 -m http.server 8765 --bind 127.0.0.1`로 정적 서버를 실행하고 `http://127.0.0.1:8765`에 접속할 수 있다. Python은 로컬 확인용이며 앱/배포 의존성이 아니다. file URL은 브라우저마다 저장소 동작이 다를 수 있어 HTTP 주소로 확인한다.

3단계 검증은 기존 사용자 데이터를 보호하기 위해 별도 테스트 주소 `http://127.0.0.1:19483/`에서 진행했다. 테스트 서버·실패 주입 도구·임시 데이터는 제출 앱 파일에 포함하지 않았다.

- **실제 Chrome 정상 흐름:** 장바구니 복원, 샷 아메리카노 2잔 + 기본 카페라떼 1잔 주문 10,500원, 재고 18/14잔·빈 장바구니·주문 1건, 새로고침 후 유지와 다음 주문 `ORD-0002`, 품절·추가 담기 차단, 입력 중 수량 반영, 다른 메뉴 옵션 유지, 키보드 조작을 확인했다.
- **Chrome에서 fixture/실패 주입:** 옵션 합산 부족·일부 메뉴 부족 주문의 부분 변경 없음, 최신 저장 재고 재검사, 반복 주문 방지, 담기·수량·삭제·주문 쓰기 실패 때 메모리/저장값 유지, 손상 JSON·버전·잘못된 데이터·읽기 실패의 변경 차단, 초과 장바구니 감소·삭제, HTML 형태 문자열의 안전한 표시를 확인했다.
- **반응형·정적 검사:** 주문/오류 화면의 360px·1280px 가로 넘침 없음, 관찰된 Chrome 오류/경고 없음, Node의 격리 데이터/계산 검증 33개, JS 문법·diff 검사 통과. 자세한 기대값·실제값은 PROMPTS 003에 기록했다.

실물 모바일 기기·다른 브라우저·스크린리더 음성·실제 용량 소진·여러 탭 동시성·Pages는 미검증이다. 저장 실패는 주입한 모의 오류이며 실제 사용자 환경에서 발생시킨 오류가 아니다. 관리자 제조 완료와 배포·ZIP은 아직 진행하지 않았다. 2단계의 이전 결과는 PROMPTS 002에 보존했다.
